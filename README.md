# RemoteGuard

원격 조작 기반 자금 탈취를 **금융 웹 세션 안에서** 탐지하고, 차단 대신 **물리적 현존 증명**으로 개입하는 시스템.

전제: 링크 차단은 실패한다. 새 도메인을 파면 뚫리고, 뚫린 뒤에는 이체까지 아무 방어선이 없다.
이 시스템은 실패를 전제로 마지막 방어선을 만든다.

---

## 지금 상태

| 구성요소 | 상태 |
|---|---|
| 수집기 (`collector/`) | 동작. 실기기에서 바로 사용 가능 |
| 특징 추출 (`shared/features.js`) | 24개 특징, 4개 층. 브라우저·Node 공용 |
| 학습 파이프라인 (`pipeline/`) | 동작. LOSO CV + 층별 ablation + 운영점 |
| API (`server/`) | 동작. 스코어링·챌린지 검증·연구용 수집 |
| SDK (`sdk/`) | 동작. 특징 벡터만 전송 |
| 데모 (`demo/`) | 동작. 모의 이체 + 흔들기 챌린지 |
| **실제 데이터** | **없음.** 이게 남은 전부다 |

현재 `data/raw`에 든 것은 전부 합성 세션이다. 파이프라인이 연결됐는지만 확인하는 용도이고,
**여기서 나온 숫자는 어떤 문서에도 쓰면 안 된다.** `train.py`가 실행할 때마다 경고를 찍는다.

## 4개 층

| 층 | 질문 | 위조 난이도 |
|---|---|---|
| **P** 포인터 | 이 터치는 물리적으로 실재하는가 | 낮음 — 압력·반경·좌표는 소프트웨어가 만들어낼 수 있다 |
| **G** 궤적 | 사람의 팔이 그린 경로인가 | 낮음 — 곡선과 보정 움직임은 합성 가능하다 |
| **T** 타이밍 | 이벤트 간격이 프레임레이트에 양자화됐는가 | 중간 — 지터를 넣으면 흐려진다 |
| **M** 모션 | 기기가 손에 들린 물체처럼 행동하는가 | **높음 — 공격자 쪽에는 기기를 움직일 API가 없다** |

`m_coupling_z`가 핵심이다. 터치 순간의 IMU 에너지를 **터치 시각을 무작위로 섞은 귀무분포와 비교한 z점수**라서,
센서 노이즈가 다른 기기 사이에서도 비교 가능하다.

`pipeline/synth.mjs`의 `remote_evasive` 조건이 존재 이유다. 소프트웨어로 만들 수 있는 신호를 전부 위조하는
적응형 공격자를 가정했을 때, P·G·T가 무너지고 M만 남는지를 ablation으로 확인한다.
**M이 여기서 버티지 못하면 그 층은 장식이므로 잘라내야 한다.**

## 실행

```bash
pip install -r server/requirements.txt

# 1. 파이프라인 점검 (합성 데이터)
node pipeline/synth.mjs --subjects 12 --per 6
node pipeline/extract.mjs
python3 pipeline/train.py
python3 pipeline/analyze.py

# 2. 서버 + 수집기 + 데모 (같은 오리진에서 서빙)
uvicorn server.app:app --host 0.0.0.0 --port 8000
#   수집기 → /collector/    데모 → /demo/
```

> **HTTPS 필수.** `devicemotion`은 secure context에서만 발생한다.
> 로컬 개발은 `ngrok http 8000`, 배포는 Vercel(프론트) + Railway/Fly(API).

## 이번 주에 할 일 — 여기서 아이디어의 생사가 갈린다

`analyze.py`가 세 가지를 검사한다. 순서대로, 앞이 깨지면 뒤는 볼 필요 없다.

1. **클럭 정렬** — `event.timeStamp`와 `performance.now()`가 같은 기준인가.
   어긋나면 결합 특징은 전부 노이즈다.
2. **실측 샘플레이트** — 60 Hz면 임펄스 검출이 아슬아슬하고, 25–30 Hz면 불가능하다.
   그 경우 M층은 임펄스가 아니라 **대역 에너지(손에 들었나 아닌가)**로 재정의해야 한다.
3. **조건 분리** — 가운데 패널(touch-triggered average)에서 handheld는 t=0에 봉우리가 서고
   remote는 평평해야 한다. 겹치면 6주 뒤가 아니라 지금 방향을 바꾼다.

최소 조건: 동의한 참여자 8명 이상, 조건당 6세션 이상, 세션당 60초 이상.
피험자가 3명 미만이면 `train.py`가 실행을 거부한다 — LOSO가 성립하지 않기 때문이다.

## 정직하게 그은 선

**범위.** 브라우저는 다른 앱의 존재를 알 수 없다. AnyDesk가 깔렸는지, 접근성 권한이 어디 붙었는지는
네이티브 SDK 영역이다. 이 MVP는 **금융 웹서비스 안에서의 세션 무결성 검증**이고, 앱 탐지·권한 점검은
상용화 로드맵에 둔다. 심사에서 반드시 물어보므로 먼저 말한다.

**위협 모델.** 페이지 자체가 공격자 통제 하에 있지 않다고 가정한다. 우리 JS를 다시 쓸 수 있는 클라이언트는
어떤 값이든 위조할 수 있다. 그건 웹의 문제가 아니라 네이티브의 문제다.

**챌린지가 막는 것과 못 막는 것.**
막는다: 완전 원격·무인 조작 (피해자가 잠든 새벽 유형 — 피해액이 큰 쪽).
못 막는다: 지시형. 사기범이 "흔들라고 나오면 흔드세요"라고 말하면 통과한다.
그쪽은 냉각 지연과 상황 질문이 담당하고, 챌린지는 마찰만 추가한다.
`shared/challenge.js` 상단에 이 구분을 명시해뒀다.

**개인정보.** `/api/v1/score`는 좌표도, 타임스탬프도, 가속도 원신호도 받지 않는다.
특징 추출은 기기에서 끝나고 24개 실수만 나간다. 원신호를 받는 `/api/v1/sessions`는
동의한 참여자 대상 연구 수집 경로 전용이고 `ALLOW_RAW_INGEST=0`으로 끌 수 있다.

**차단하지 않는다.** 정상 이체를 막으면 서비스가 죽는다. 정책은 3단계(허용 / 챌린지 / 챌린지+지연)이고
하드 블록이 없다. `_imu_alone_guard()`는 M층 단독으로는 절대 상위 밴드로 못 올라가게 막는다 —
거치대에 놓고 쓰는 정상 사용자가 원격 세션과 똑같은 평평한 IMU를 만들기 때문이다.

**하지 않은 것.** 실제 은행 사이트를 복제하지 않았고, 악성 앱을 만들지 않았다.
모의 화면은 상단에 그렇게 표시된다. 데이터는 본인 기기와 동의한 참여자에게서만 수집한다.

## 평가 지표

`train.py`가 출력하는 것 중 발표에 실을 것:

- **층별 ablation** — 다층 설계의 정당성. `remote_evasive` 포함/제외 두 벌로 돌린다
- **운영점 표** — FPR 예산별로 얻는 재현율. "95% 재현율" 대신 은행이 감당할 오탐률에서 시작한다
- **조건별 오탐률** — 특히 `desk`. 배포 가능 여부를 결정하는 숫자
- **세션 단위 경보 시각** — 이체 버튼 이전에 잡았는가

AUC는 헤드라인이 아니다. 랜덤 분할 AUC는 더더욱 아니다.

## 구조

```
shared/features.js     24개 특징. 브라우저와 Node가 같은 파일을 쓴다 (train/serve skew 없음)
shared/challenge.js    물리적 현존 검증. 요약 8개 값 + 임계 판정
collector/index.html   Phase 0–1 수집기. 라이브 결합 계측 포함
sdk/remoteguard.js     한 줄로 붙이는 SDK. 특징만 전송, 실패 시 fail-open
server/app.py          스코어링 · 챌린지 검증 · 연구용 수집 · 정책 밴드
demo/index.html        모의 이체 + 흔들기 챌린지
pipeline/synth.mjs     합성 세션 (파이프라인 점검 전용)
pipeline/extract.mjs   raw → windows.csv
pipeline/train.py      LightGBM + LOSO + ablation + 운영점
pipeline/analyze.py    Phase 0 신호 검증 플롯
```
